# DEMAX AI Assistant — демо адмін-панелі з живим RAG

Демонстраційний стенд платформи **DEMAX AI Assistant**: адміністративна панель і AI-консультант,
що відповідає **виключно** на основі бази знань бренду DEMAX (сайт + каталог продукції).

🌐 **Демо:** [demax.kindrakevich.com](https://demax.kindrakevich.com)

---

## Що це

Проєкт складається з двох частин:

| Частина | Технології | Призначення |
|---|---|---|
| **`demax-admin/`** | React 19 · TypeScript · Tailwind CSS v4 · Vite | Адмін-панель: 13 модулів, ~30 екранів, три мови (UK/RU/EN), світла й темна теми |
| **`demax-rag/`** | Python 3.12 · FastAPI · PostgreSQL 16 + pgvector | RAG-бекенд: індексація бази знань, гібридний пошук, генерація відповідей |

### Адмін-панель

Дашборд · AI-асистент · Клієнти (360°-профіль) · Діалоги · Ескалації · Верифікація спеціалістів ·
База знань (Markdown-редактор із workflow публікації) · Семінари · Розсилки · AI-моніторинг ·
Аналітика · Персонал і ролі · Журнал аудиту · Переклади · Налаштування.

Особливості: повна локалізація (жодного захардкоденого рядка), доступність WCAG 2.1 AA,
адаптивність, курсорна пагінація, масові дії, підтвердження незворотних операцій.

### AI-консультант (RAG)

Плаваючий віджет на кожній сторінці панелі:

- **Відповіді лише з бази знань** — модель не вигадує фактів. Коли даних немає,
  каже про це прямо; скарги, медичні та комерційні питання передаються менеджеру.
- **Посилання на джерела** під кожною відповіддю + оцінка впевненості.
- **Мова відповіді = мова інтерфейсу** — перемикач UK/RU/EN у шапці керує мовою консультанта
  незалежно від мови запитання чи мови бази знань.
- **Картки товарів** — коли доречно, асистент показує фото з каталогу, ціну
  й посилання на сторінку товару, а не лише текст.
- Ознака «ви спілкуєтеся з AI» (вимога EU AI Act).
- Розмова зберігається: при поверненні видно попередню переписку.

### AI-звіти по системі (⌘K)

Рядок у шапці панелі — не пошук, а запитання. Менеджер питає «що зараз
важливо?» і отримує персональний брифінг: свої ескалації, черга верифікацій,
заповнюваність семінарів, прогалини в базі знань. Чотири швидкі звіти або
вільне запитання, три мови.

## Як працює RAG

```
Джерела                    Обробка                      Пошук і відповідь
─────────────────────      ────────────────────────     ──────────────────────────
demax.com.ua (sitemap) ┐   витяг тексту                 запит користувача
PDF-каталог            ├─► чанкування (~1100 симв.) ──► ембедінг запиту
                       ┘   локальні ембедінги           ├─ pgvector cosine (HNSW)
                           (multilingual MiniLM)        ├─ повнотекстовий пошук
                           збереження в PostgreSQL      └─ злиття RRF → top-5
                                                        ↓
                                                        LLM (лише з контексту)
                                                        ↓
                                                        відповідь + джерела
                                                        або ескалація менеджеру
```

**Ембедінги рахуються локально** (ONNX, без зовнішніх викликів) — у базу знань нічого не
надсилається назовні. Зовнішній LLM використовується лише для формулювання відповіді
з уже знайдених фрагментів.

## Локальний запуск

Потрібні **Docker** і **Node.js 22+**.

### 1. RAG-бекенд

```bash
cd demax-rag
cp .env.example .env          # додайте OPENAI_API_KEY або ANTHROPIC_API_KEY
docker compose up -d --build
```

Під час першого запуску сервіс автоматично проіндексує базу знань
(сайт demax.com.ua + PDF-каталог) — це займає ~5 хвилин.

Перевірка стану:

```bash
curl http://localhost:8100/v1/health/ready
```

### 2. Адмін-панель

```bash
cd demax-admin
npm install
npm run dev                   # http://localhost:5173
```

Або через Docker (production-збірка за nginx):

```bash
cd demax-admin
docker compose up -d --build  # http://localhost:5199
```

## API

Реалізовано підмножину ендпоінтів згідно зі специфікацією проєкту:

| Метод | Шлях | Призначення |
|---|---|---|
| `POST` | `/v1/me/conversations/messages` | Повідомлення асистенту (відповідь із джерелами або ескалація) |
| `POST` | `/v1/admin/knowledge/search` | Гібридний пошук по базі знань (превʼю того, що «бачить» AI) |
| `GET` | `/v1/admin/knowledge/articles` | Статистика бази знань за джерелами |
| `POST` | `/v1/admin/knowledge/reindex` | Перезапуск індексації |
| `GET` | `/v1/me/conversations/{id}/messages` | Історія розмови (віджет відновлює її при відкритті) |
| `POST` | `/v1/admin/insights` | AI-звіт по стану системи для конкретного менеджера |
| `GET` · `PUT` | `/v1/admin/translations` | Переклади інтерфейсу з бази (читання й редагування) |
| `GET` | `/v1/health` · `/v1/health/ready` · `/v1/version` | Стан сервісу та залежностей |

Приклад запиту:

```bash
curl -X POST http://localhost:8100/v1/me/conversations/messages \
  -H 'Content-Type: application/json' \
  -d '{"text":"Який крем підійде для сухої шкіри?","language":"uk"}'
```

## Розгортання

Сервер працює під керуванням **aaPanel**: база даних, Python-проєкт і сайт налаштовуються
через веб-інтерфейс панелі й там же моніторяться. Деплой автоматичний — push у `main`
запускає GitHub Actions.

Покрокова інструкція: **[DEPLOY.md](DEPLOY.md)**

## Структура

```
demax-admin/           # React-адмінка
  src/
    assistant/         # віджет консультанта + AI-звіти по системі (⌘K)
    components/        # UI-кіт (таблиці, форми, графіки)
    layout/            # оболонка: сайдбар, топбар
    pages/             # екрани модулів
    lib/               # локалізація, демо-дані
demax-rag/             # FastAPI + PostgreSQL
  app/
    main.py            # HTTP-ендпоінти
    rag.py             # пошук, картки товарів, генерація відповіді, звіти
    ingest.py          # індексація сайту та PDF
    embeddings.py      # локальна модель ембедінгів
    db.py              # схема та підключення до БД
.github/workflows/     # автоматичний деплой
```

## Безпека

Повний опис моделі загроз, потоків даних і того, що треба закрити перед
продакшеном — у **[SECURITY.md](SECURITY.md)**. Стисло:

**Секрети.** У репозиторії немає жодного ключа, пароля чи токена — усе через
`.env`, який не потрапляє в git. На сервері файл має права `600`. Матеріали
замовника (специфікації, комерційні документи) також виключені з репозиторію.

**Що залишає периметр.** Ембедінги рахуються локально (ONNX, без мережі), тож
база знань нікуди не надсилається. До зовнішнього LLM іде лише запитання
користувача разом із кількома знайденими фрагментами — рівно стільки, скільки
потрібно для відповіді.

**Персональні дані.** База знань складається з публічних сторінок сайту й
каталогу — персональних даних у ній немає за побудовою. Дані клієнтів у демо
вигадані.

> ⚠️ **Демо не має шару автентифікації.** API відкритий, бо це стенд для
> показу. Специфікація вимагає JWT (RS256), MFA для персоналу й перевірку прав
> на рівні рядків — це перше, що реалізується в продакшн-версії. Перелік усіх
> розбіжностей між демо та продом — у [SECURITY.md](SECURITY.md).
